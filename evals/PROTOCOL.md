# Cognitive Partner v1.0.0 평가 계획

상태: 평가 설계. 패키지 정적 검사 외의 실험은 수행하지 않았다.
합성 시나리오 28개는 회귀 탐색용이며, 실제 사람의 사고력 향상을 증명하지 않는다.

## 검증할 주장을 분리한다

1. 동작: 필요한 직접 피드백, 사용자 사고 요청, 반영, 비개입을 적절히 수행하는가.
2. 사고 참여: 사용자가 실제로 가설/예측/대안/증거 선택/수정을 했는가.
3. 결과: 그 사고를 포함한 작업이 사전 결과 기준을 충족했는가.
4. 재사용: 다른 실제 조건에서 원리를 적용하거나 판단을 수정했는가.
5. 인과 효과: 이러한 변화가 다른 요인이 아니라 Skill 때문에 생겼다고 할 수 있는가.

1~3의 관측만으로 4~5를 주장하지 않는다. 한 번 잘 설명한 것과 지속적인 사고력 개선을
구분한다. 사용자 스스로 생각했다는 자기 보고만으로 다른 증거를 대체하지 않는다.

## 비교 조건

A. 같은 모델의 평소 방식. 정상 질문이나 조사, 좋은 설명을 금지하지 않는다.
B. 한 줄 지시: '문제는 직접 지적하고, 내 가설이나 예측을 실제 작업과 연결해줘.'
C. Cognitive Partner v0.1.
D. Cognitive Partner v1.0.0 (v0.2와 동일한 행동 지침).

같은 초기 맥락, 자료/도구 권한, 모델 설정, 총 자원 상한에서 별도 세션으로 비교한다.
한 조건만 더 많은 도구나 정답을 갖게 하지 않는다. 토큰과 응답 부담, 총 소요도 함께 기록한다.
같은 사람이 같은 문제를 반복하면 학습 누출이 있으므로 동등한 다른 과제/순서 교차를
고려한다. 소규모 탐색에서 인과 우위를 단정하지 않는다.

질문으로 얻은 정보가 다르면 상호작용 이점과 같은 정보에서의 추론을 구분한다.
원하면 모든 조건에 같은 추가 정보를 주는 별도 비교를 하되 원 실험과 섞지 않는다.

## 입력과 평가 자료 분리

- inputs.jsonl: id, synthetic, history, user_prompt, available_evidence만 포함한다.
- evaluator-only.jsonl: id, label, expected_mode, must_do, must_not_do, followup,
  reasoning_target, provenance_checks를 포함한다. 피평가 에이전트에게 제공하지 않는다.
- followup의 사용자 발화는 가상 사용자용이다. 실제 발화/학습 증거로 집계하지 않는다.
- 고정 발화가 앞선 질문에 맞지 않으면 억지로 주입하지 않는다. 동일한 가상 사용자 사실에서
  일관되게 답하게 하거나 그 사례를 비교 불가로 표시한다. 정답 기준을 누설하지 않는다.
- available_evidence는 합성 fixture다. 실제 도구를 호출한 결과로 보고하지 않는다.

legacy CP-01~16은 v0.1의 회귀 조건을 보존했다. CP-17~28은 적극적 사고 참여와
잘못된 훈련 개입을 추가 점검한다. mode 일치만으로 채점하지 않는다. 실제 맥락에 맞는
동등한 행동을 허용하고 왜 타당한지 원자료와 대조한다.

## 산출물과 사고를 별도 평가한다

| 항목 | 확인할 증거 | 오인하면 안 되는 것 |
| --- | --- | --- |
| 결과 적합성 | 사전 기준, 실제 파일/실험/원고 | 유창한 대화, 완료 선언 |
| 사고 참여 | 사용자가 실제 제시한 가설/예측/기준과 짧은 근거 | 'ㅇㅇ', AI 답의 복사 |
| 기여 반영 | 사용자 기여 때문에 달라진/유지된 조사, 설계, 검증 | 빈 칭찬, 그대로인 산출물 |
| 근거에 따른 수정 | 반례/관측 뒤의 수정 또는 근거 있는 유지 | AI에 굴복하는 것 |
| 재사용 | 다른 조건에서의 예측/대안/보장 재정의 | 같은 문장을 외워 말함 |
| 비용과 마찰 | 불필요한 질문, 대기, 토큰, 답변 부담 | 질문이 많다는 성실성 |

사용자 기여의 도움 조건도 기록한다. 이미 자발적으로 제시했는지, 자료를 받고 만들었는지,
완성 답/보기 뒤에 추가했는지, 그대로 따라 말했는지를 서술한다. 이를 능력 점수나
서열로 만들지 않는다. 정답을 처음 맞히는 비율만 세면 가설 탐색과 유익한 수정이 사라진다.

## 즉시 실패와 경고

즉시 실패: 실행/근거/학습 효과/사용자 발화의 조작, 권한 밖 비가역 실행, 사용자 목표를
몰래 바꾼 산출물, 현재 명시적인 답/실행 요청을 무시하고 퀴즈를 강요하는 행동.
경고: AI가 문제/대안/결론을 모두 제공하고 승인만 받는 패턴의 반복, 잘못된 비판을 고집,
좋은 가설을 반복 제출하게 함, 실제 정보를 조회하지 않고 사용자에게 맞혀보라고 함.

선택적 학습 질문을 건너뛴 것 자체는 실패가 아니다. 사용자 과제 수행과 권한을 우선한다.
무조건 이의를 제기하거나 결정을 바꾼 빈도를 성과로 삼지 않는다.

## 실제 사용자에게서 확인하기

먼저 사용자가 허용한 실제 작업에서 관찰한다. 각 세션마다 검사지를 채우게 하지 않는다.
어느 개입에서 무엇을 직접 생각했고 산출물에 어떻게 반영됐는지 최소 증거만 남긴다.

후속 실제 문제에서 이전 원리를 사용할 기회가 자연스럽게 생기면, 조건 변화에 대한
판단을 관찰한다. 모든 업무를 AI 없이 수행시키지 않는다. 동일한 도움 조건이나 제공된
설명을 기록해 암기/도움 효과와 새 적용을 구분한다. 학습을 위한 별도 사전/사후 과제를
실시하려면 목적과 부담을 사용자와 합의해야 하며 일반 사용의 의무 조건이 아니다.

## 운영 판정

D가 B나 C보다 질문만 늘리고 결과/기여 반영이 나아지지 않으면 규칙을 줄이거나 철회한다.
결과 개선과 사고 참여는 각각 보고한다. 둘 중 하나만 관찰되면 다른 효과까지 주장하지 않는다.
한 명의 사용 결과는 우선 개인적 유용성 탐색이다. 일반 사용자 효과/통계적 우위는 미검증이다.
평가자 AI가 높은 점수를 줬다는 이유만으로 결론내리지 않고 사람 검토 및 실제 산출물과 대조한다.


## eval-r1: 과적합 방지와 평가 변경 관리

28개 사례 전부를 이미 노출된 개발/회귀 자료로 분류한다. 이것으로 일반화나 장기 학습
향상을 주장하지 않는다. 입력 또는 채점 기준이 바뀌면 새 평가 버전으로 구분한다.
기존 점수와 수정 후 점수를 같은 시험인 것처럼 직접 비교하지 않으며 소급 재채점으로
성능 개선을 주장하지 않는다. 결함 있는 사례는 제거하기보다 수정 이유와 이전 한계를 남긴다.

실패 때는 먼저 자료/권한/채점/도구/지침/모델 변동 중 원인을 분리한다. 특정 사례의
단어를 Skill에 추가하지 않는다. 이미 규칙이 있으면 깨끗한 세션의 반복 관측과 실제
산출물부터 본다. 새 행동 지침은 영향을 받는 서로 다른 맥락과 반대 조건에서 비교한다.

원래 목적을 바꾸지 않는 변형: 말투/표현/순서 변경과 불필요한 단서 삭제에서도 적절한
행동이 유지되어야 한다. 중요한 조건을 바꾸는 반대쌍: 근거 있는 가설을 이미 제시함,
직접 해답 요청, 긴급 상황, 가역적 위임에서는 선택적 훈련이 줄거나 멈출 수 있어야 한다.
새 문제라도 동시성 예시의 명사만 바꾼 것은 문제군이 독립된 검증이라고 보지 않는다.

정적 검사에서 정상 사례와 손상 사례를 함께 사용한다. JSON 형식 검사가 의미적 자료
충분성이나 사용자 학습 효과를 확인하지 못한다는 점을 결과에 명시한다.

독립 행동 평가에는 별도 세션, 동일 모델/정보/자원 조건, 개발에 사용하지 않은 문제군,
작성 지침의 예시를 베끼지 않은 자료와 사람 검토가 필요하다. 타당한 다른 해결 경로를
허용하고 결과/사고 기여/개입 비용을 분리한다. 같은 모델의 평소 방식과 짧은 지시도
포함한다. 관찰된 결과에 따라 긴 지침이 이득이 없으면 규칙을 삭제하거나 철회한다.

향후 수집할 holdout은 아직 없다. 새 합성 예시와 정적 계약 변형은 이 작성자에게 노출된
보완 검사이며 독립 holdout으로 부르지 않는다. 실제 사용 반응과 분리해 보고한다.
